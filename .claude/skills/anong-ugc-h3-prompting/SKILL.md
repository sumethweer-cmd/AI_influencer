# Anong UGC × MiniMax H3 — การเขียนบท/shot/prompt

ใช้คู่กับ `drama-h3-production` (รูปแบบ H3 6 หัวข้อและบทเรียนจากละคร: `references/prompt-format.md`) และ `ugc-render-ops` (สั่งเรนเดอร์). ข้อมูลตัวละครอยู่ใน `characters/` และ `model_specs/minimax-h3.md` ของ repo; ในเครื่องผู้ใช้ชุดทำงานอยู่ที่ `UGC/` (Anong Character, Albums, Backgrounds, Weekly/<สัปดาห์>/<NN_เรื่อง>/) — **รูปและอัลบั้มไม่อยู่ใน repo**. อย่าผสมตัวละคร/รูป/canon กับโปรเจกต์ละคร (short-parking-001) ตามกฎของ studio

## 1. งานทีละเรื่อง (ลำดับ)
1. อ่านบท + `INDEX.md` ของสัปดาห์ + เสียงตัวละคร (`speaking_style.md`: "หนู", เรียก "พี่ๆ", ลงท้าย ค่ะ/คะ/นะ อบอุ่นหยอกเล็กน้อย ไม่ท่องบท)
2. **ตรวจบทให้เป็นภาษาพูด** — ทำตารางเดิม → เสนอ → เหตุผล (ตัวอย่าง: "หนึ่งเส้น"→"เส้นเดียว", เติม "นะ/ค่ะ", ตัดประโยคยาวซ้อนเป็นสองท่อน). ตรวจเนื้อหาสุขภาพตามกฎ trust: FACT / INTERPRETATION / OPINION, ไม่อ้างแพทย์/วินิจฉัย ("มีได้หลายสาเหตุ", "…เสมอไป", ให้ "ปรึกษาหมอก่อน"), ไม่มีของเกินจริง/ก่อน–หลังปลอม. เก็บความหมายเดิม ผู้ใช้ตัดสินเรื่องถ้อยคำ
3. **ประเมินความยาว**: ไทย ~2.5–3 คำ/วินาที + จังหวะ (เป้ารวมของชุดนี้ 30–45 วินาที; ถ้าเกินให้บอกผู้ใช้พร้อมตัวเลือกตัดจุดไหน)
4. **แบ่ง segment ≤ 15 วินาที** แบ่งที่รอยต่อประโยค ไม่ตัดกลางประโยค (ตัวอย่าง Gray Hair: SEG1 14 วินาที/336 เฟรม, SEG2 13 วินาที/312 เฟรม, SEG3 ~13, SEG4 ~9–10). 1 เรื่อง = 1 job ที่ต่อทุก segment
5. **ออกแบบ shot** เป็นตาราง (shot / เวลา / ขนาดภาพ / action / เสียง) แล้ว **ตรวจ logic ของ motion** (หัวข้อ 3) ก่อนเขียน prompt
6. เขียน `H3_SEG<N>_prompt.txt` (ไม่มี header; ขึ้นต้น `subject_definitions:`) + `H3_PLAN.md` ของเรื่อง (รูปที่ใช้, ตารางตรวจบท, แบ่ง segment, shot/logic, การตัดสินใจ/ความเสี่ยง) → ให้ผู้ใช้ตรวจก่อนสั่งเรนเดอร์
7. ส่ง prompt เข้า Supabase (`supabase_prompts.mjs --push` ดู `ugc-render-ops`) เมื่อผู้ใช้อนุมัติ

## 2. รูปที่ใส่ (ทุก segment ของเรื่องเดียวกันใช้ชุดเดิม)
- **Picture 1 = Anong** (รูปจาก Albums ที่หน้าชัดใหญ่) · **Picture 2 = ฉากหลัง** (จาก Backgrounds; 1 ฉากต่อเรื่อง) — บอกผู้ใช้เสมอว่าใช้รูปไหน และ prompt ต้องกล่าวถึงเฉพาะ Picture ที่ใช้จริง
- **ข้อความมีน้ำหนักเหนือรูปเมื่อขัดกัน** (ทดสอบแล้ว: รูป Dinner ชุดดำเปิดไหล่ แต่ข้อความบอกเสื้อยืดเขียว → ได้เสื้อเขียว). ถ้าไม่ระบุชุดในข้อความ รูปจะกำหนดชุด/ห้องตามรูป → ใช้ได้ถ้าต้องการสลับรูปโดยไม่แก้ prompt
- สิ่งของในรูปที่ไม่ต้องการ (เช่น แก้วมัก) ให้ระบุมือ/ของที่ถืออย่างชัดเจนใน prompt (มือขวาถือกระจก มือซ้ายว่าง) — ตัวละครที่ไม่อยู่ในฉากต้องระบุว่าไม่อยู่ (บทเรียนละคร)
- ตรวจรูป Picture 1 ก่อนใช้: เหล็กดัดฟันตอนยิ้ม, ของถือ, เสื้อผ้าที่ไม่เข้ากับฉาก
- เทียบรูปที่ผู้ใช้ใช้จริงกับรูปที่คิดไว้ด้วย sha256 ถ้าผลไม่ตรง (เคยเจอใช้ผิดรูป)
- ผลที่เจอ: **framing กว้างกว่าที่เขียน** (เห็นเต็มโซฟา/ขา) แม้เขียน "medium close-up" — องค์ประกอบของ Picture 1/2 มีผลต่อ framing → ใช้ Picture 1 ที่หน้า–อกเต็มเฟรม และ/หรือเขียนกำกับหัว–อกชัดๆ; ยังเป็นประเด็นเปิดอยู่

## 3. UGC นั่งพูดหน้ากล้อง — กฎ shot / motion
- กล้องเป็นมือถือตั้งขาตั้ง/พิงไว้ระดับสายตาคนนั่ง **นิ่งตลอด** มีแต่ตัวละครขยับ; ตัดเฉพาะ **ขนาดภาพ** (MCU หัว–อก ↔ CU หัว–ไหล่) มุมเดิมฉากเดิม
- แสง: นุ่มจากด้านหน้า ให้สองข้างหน้าสว่างเท่ากัน (ถ้าฉากหลังมีแสงหน้าต่างด้านข้าง ให้เขียน "แสงหน้าต่าง + ไฟเติมนุ่มจากฝั่งกล้อง"); ไม่ใช้แสงสีจากฉากหลังตกบนผิว
- ผิว (แนวสมจริง): ระบุละเอียด dry matte, รูขุมขน, ขนอ่อนแก้ม, กระจางๆ, ความไม่เรียบเล็กน้อยรอบจมูก/คาง และ T-zone matte; หลีกเลี่ยง flawless/dewy/glow/shimmer/highlighter/wet skin; ไม่เขียนผิวละเอียดในภาพไกล. แต่งหน้า "minimal matte + soft lip tint" (DNA เดิมมี dewy — ตัดสินใจใช้ matte ในงานชุดนี้ ไม่ได้แก้ไฟล์ DNA)
- **logic ที่ต้องตรวจทุก shot:** ของในมือ (ถือมือไหน, วางลงเมื่อไหร่, ไม่มีของเปลี่ยนมือ/เพิ่มมือ), 1 action หลักต่อ shot, ทุกท่ามีเหตุจากบท, สายตา (มองกระจก/มองเลนส์), เวลาที่ shot ≥ เวลาพูด, ไม่มีสิ่งที่บทห้าม. ท่าละเอียดหลายนิ้วในเวลาสั้น (ไถมือถือกลางอากาศ + แหวกผม) เสี่ยงมือเพี้ยน → ท่าเดียวต่อ shot
- จบ segment ก่อนหน้าต้องเขียน "สถานะจบ" (นั่งตรง ของในมืออะไร มือว่างข้างไหน) แล้ว segment ถัดไปเปิดต่อจากสถานะนั้น

## 4. โครงสร้าง prompt (รูปแบบที่ใช้ใน SEG1/SEG2 ของ Gray Hair ซึ่งผู้ใช้เรนเดอร์แล้ว)
6 หัวข้อ: `subject_definitions` / `summary` (`[reference generation]`, บอกว่า Picture 1 กำหนดตัวตน/ผิว/ชุด, Picture 2 กำหนดฉาก) / `retention_analysis` / `detailed_description` (`[Shot N]`, เวลา `At 00:03.520`) / `overall_soundscape` / `non_diegetic_music` (`N/A`)
- บทพูดไทย: `<d>[Thai] …</d>` ความเร็ว ~2.5 คำ/วินาที; จังหวะหยุดเขียนตัวเลขวินาที ("holding about 0.4 seconds"); บอกน้ำเสียงต่อประโยค ("at a playful, slightly dramatic pace")
- **segment แบบ context** (SEG2+): เวลา +0.92 วินาทีจากที่คำนวณ, เปิดด้วยบล็อกต่อเนื่อง ("video opens already in progress… same position…"), ต่อที่รอยต่อประโยค, ใส่สถานะมือ/ของให้ตรงกับตอนจบ segment ก่อน
- เขียนเชิงบวก (หลีกเลี่ยง no/not/without) แต่ **ถ้าต้องกันของ/คนที่ไม่ควรอยู่ในฉากให้ระบุชัด** (ผลทดสอบละครชี้ว่าได้ผล n=1; ถ้าจะตัดสินให้ A/B)
- ตรวจ prompt ด้วยสคริปต์ก่อนส่ง: ไม่มีคำ no/not/without, ไม่มี dewy/glow/flawless, ช่วงเวลา shot ต่อเนื่องและรวมไม่เกินความยาว segment, frames = วินาที×24 และ frames × MP ≤ ~540 ต่อ segment (1.2 MP ได้ถึง ~15 วินาที)

### ⚠ สถานะที่ยังต้องทดสอบ (อย่าสรุปเป็นกฎ)
เอกสารของ workflow ("Longprompt writer": README + LLM system prompt สำหรับ Motion Context V2) ระบุกฎที่ **ต่างจากรูปแบบข้างบน** — ผู้ใช้ยังไม่ได้ตัดสินใจสลับ:
1. หนึ่ง `[Shot 1]` ต่อ segment และแบ่งจังหวะด้วยช่วงเวลา `00:03.920-00:06.000: …` ห้ามคำว่า "cut" (SEG1/2 ของเราเขียน 5 shot + "camera cuts to"; ถ้าต้องการสลับขนาดภาพอาจทำ punch-in ตอนตัดต่อแทน)
2. ตัวตน: `<Subject 1> is the young woman whose face, hair and outfit come entirely from <Picture 1>.` แล้วหยุด (ไม่บรรยายผม/ชุดยาว)
3. บทพูด: `At 00:04.700: [speaking, <Language>, <voice description>, <tone>] "line"` (voice description เต็มบรรทัดแรกของ segment แล้ว "same voice"); มี `<Audio 1>` อ้างอิงเสียงให้คงเสียงข้าม segment — ต่างจาก `<d>[Thai]…</d>`
4. รูปอ้างอิงใส่เฉพาะ segment 1 ("Use as shared reference"); ไม่ใส่รูปสถานที่ใน segment หลัง (ทำให้เริ่มที่ใหม่ = เหมือนตัด) — ปัจจุบันสคริปต์ส่งรูปทุก segment
5. Steps: default 8 (เสียงเพี้ยนเมื่อต่อหลาย segment ถ้าต่ำ); 6 ใช้ได้เมื่อฉากสงบ; 4 ทำให้พยางค์ไทยหาย → เสียงไทยเริ่มที่ 8
6. Spec ของ Singularity (HF `WarmBloodAban/Minimax-h3_Singularity`) แยก `<Subject N>` กับ `<Picture N>` — ขัดกับสเปคทีม ทดสอบก่อนสลับ
ถ้าผู้ใช้ต้องการ ให้ทดสอบ A/B (เรื่องเดียวกัน 2 รูปแบบ) แล้วค่อยสรุป; บันทึกผลใน `H3_PLAN.md`

### คำแนะนำภายนอกที่ยังไม่ยืนยัน (จากภาพหน้าจอ ไม่ทราบแหล่ง)
trigger word `r34l1sm` บรรทัดแรกเมื่อเปิด People LoRA (ยังไม่ทราบว่า workflow มี LoRA นี้หรือไม่ → ถามผู้ใช้), บทพูด ~3 ท่อนสั้นต่อ 12 วินาที (ของเรา 5 ท่อนต่อ 14 วินาที → ถ้าปากไม่ซิงก์ให้ลดจำนวน shot ก่อน), 1.2–1.4 MP รอบเดียว ไม่ upscale รอบสอง, reroll ด้วยเปลี่ยน seed, ข้อกล่าวว่า "H3 ตีความคำปฏิเสธเป็นสิ่งที่ต้องทำ" (ผลทดสอบละคร n=1 ขัดกับข้อนี้) — ใช้เป็นสมมติฐานที่ต้องทดสอบ

## 5. ผลทดสอบที่ผ่านมา (Gray Hair)
